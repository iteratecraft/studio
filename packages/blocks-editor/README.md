# @course-suite/blocks-editor

The blocks editor's screens (M2-08 onward, BLK-01): runtime-neutral React that reaches files,
dialogs and the window only through `@course-suite/host` (ADR-0006), edits courses only through
`@course-suite/doc-ops` commands, keeps them in `@course-suite/project` files and draws everything
with `@course-suite/ui` and its string catalogue. Apache-2.0, layer `ui`. `apps/desktop` runs it
over the desktop host; `apps/web` serves it at `editor.html` over the in-memory host for the
browser tests.

```tsx
import "@course-suite/ui/styles.css";
import "@course-suite/blocks-editor/styles.css";
import { BlocksEditorApp } from "@course-suite/blocks-editor";

createRoot(element).render(<BlocksEditorApp host={host} locale="en" />);
```

The course list lives in the host's storage (`library`), with what each card shows, so the
dashboard never reads the course files; on launch it only asks the host when each file last
changed (`HostFiles.modified`), which also tells which are gone.

`CourseSession` (one open course: editor, autosave, save, discard, save state, media for the preview
and media files pasted from another course) and the session's change events are what later editor
screens build on.

## Block types

`blocks.tsx` lists every block type with what it brings (the BLK-03 block-type contract): its
library group and name, `create` (a new block with sample content, from the string catalogue),
`Fields` (its content, edited in place through doc-ops commands), `Format` (its own options, shown
in the format menu after the common ones) and `switchable` (sibling types it can turn into, keeping
its content; `family` narrows the siblings where a group holds several). The text and static types
live in `static-blocks.tsx`, the interactive ones (M2-14) in `interactive-blocks.tsx`; their settings, with their
defaults, are the format's (`variantSettings`). A type without `create` is listed as not available yet. A
later block epic adds its type there; the lesson, the library, copy and paste, manage blocks and
the style and format menus take it as it is.

## Size

Built for the browser (`pnpm --filter @course-suite/web build`, then `size`, gzip -9): this package
with the engine packages it uses (doc-ops, format, host, jobs, project, zip) is 70.3 KB gzipped,
script and style, on top of React (65.8 KB), React Aria (121.1 KB) and the kit (25.2 KB);
`editor.html` loads 284.0 KB in all. The block previews (the player's block renderer and style
sheet, 16.3 KB) load with the first lesson opened, and the player chunk of the course preview
(67.0 KB) with the first preview. On top of M2-12 and M2-13, the theme panel and the author's fonts
(M2-17) add 11.0 KB to this package, 1.7 KB to the kit and 6.5 KB to the player chunk: 12.7 KB more
for `editor.html`. Knowledge checks and quiz lessons (M2-15) add 4.3 KB to this package, 0.9 KB to the
kit (strings), 0.4 KB to the block previews and 1.3 KB to the player chunk: 5.3 KB more for
`editor.html` (289.3 KB). Navigation and continue settings (M2-16) add 5.1 KB to the player script and
2.0 KB to its style sheet; all the app's scripts and styles together grow by 11.5 KB, the player chunks
included. The publish panel and export (M2-18) add 5.7 KB to this package with the engine code it
uses (the format's publish settings, the job runner) and 1.6 KB to the kit (strings): 7.4 KB more
for `editor.html` (325.2 KB). The progress estimate loads with the player chunk when the panel
opens; the export worker (174 KB gzipped: exporters, player and schema files) loads only when a
package is built, and adds 0.25 KB to the player script. The bundled fonts (24 files, 451 KB, already compressed) load only when a page
draws text in them. No dependency.

Limits: a media file may be at most 2 GiB (the spec allows 5 GB, UI-BLOCKS-EDITOR-R34), as a
project file holds 4 GiB in all without ZIP64 and is held in memory while saved; a file picked in
the open dialog is read before its size is known. The preview sends every media file to its frame
on each update, so very large videos make updates slow.
